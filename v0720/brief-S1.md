## Lead decisions for S1 (win over the spec)
- **L6 in-game build list.** In S1 the in-game build list is only the default title (`MUSIC_TITLE_DEFAULT_ID`). The mission family L0–L2 is NOT built in S1 (it is not played until S2; do not hold 4.2 MB unused). Design the build queue as an ordered list so S2 only appends the family (§13 L1 order: current scene's music first, then default title, then family).
- **L7 work buffer and tables.** Allocate the work buffer (`MUSIC_WORK_SAMPLES`) and `MusicTables` lazily when the first build starts (not at Boot). Drop the work buffer (null) when the queue is empty; the lab re-allocates on demand. Tables may stay (0.44 MB) — say which you chose and why.
- **L8 one copy.** Copy each finished result into `ctx.createBuffer(1, n, MUSIC_SAMPLE_RATE)` (`copyToChannel` or `getChannelData(0).set`) in the frame it finishes, and keep no other Float32 copy.
- **L9 budget.** Keep the fixed 150,000 units/frame (deterministic partition). Record build timing for gates/debug in `stats()` without allocation (e.g. count, max ms, and a fixed-size histogram or ring of Float64). Do not adapt the budget in S1; if the headless Title-build p95 gate fails, report it with numbers and a proposal instead of silently changing the budget.
- **L10 late readiness.** If a scene asks for music that is not built yet, start it when it becomes ready if that scene still wants it (first fade-in `MUSIC_FADE.firstInS` 2 s). No source is ever created for an unready buffer.
- **L11 context.** Never create sources or schedule automation while the context is not `running` (CLAUDE.md §7 row "止まっている context に音を積まない"). When it becomes running (first touchend on iOS, return from background), the 10 Hz update starts what the current scene wants. Phaser's blur suspend/resume must not restart music (the looping source just continues).
- **L12 mute vs 曲.** 「音: オフ」 (master 0, existing) also stops music sources after `MUSIC_FADE.muteStopS`; 「音: オン」 restarts the scene's music from the head. 「曲: オフ」 fades the music bus to 0 in `musicOffS` then stops the sources; 「曲: オン」 restarts from the head. The two settings are independent and persisted separately (`night-hunters.sound` existing, `night-hunters.music` new; same try/catch style as `sfx-settings`).
- **L13 release.** `MissionSfx` (created by HudScene) calls `sfxMusic(MUSIC_CTX_MISSION)` on create and `sfxMusicRelease(MUSIC_CTX_MISSION)` on shutdown. Release only acts if the current context is still MISSION. Test both orders (Phaser 3.90 runs Hud SHUTDOWN after Result/Title create — spec §4.2).
- **L14 lab.** `?sfxlab` opens the new music lab (`MUSIC_CTX_LAB`). Row 0: 「A 静かな夜の海」「B 小太鼓と金管」「C ラジオの哀愁」「止める」 (default marked 「（今）」 the same way the v0.7.1 lab marks defaults — see the IP fix where the selected button shows only the letter + （今） to avoid overflow). Bottom row: 「戻る（タイトルへ）」, 「効果音の試聴へ」 (the v0.7.1 lab), and a status line (「作成中… 40%」 / 「鳴らしている: A」). First tap on a candidate starts its build and shows 「作成中…」 on that button; when ready it plays as the continuation of that tap (no second tap needed). Tapping the playing candidate stops it; another candidate crossfades `labCrossS` 0.5 s. Candidate buttons are `silent` (no ui_tap). The top explanation includes a request like 「知っている曲に似ていたら一言ください」. On leaving the lab, drop non-default buffers. The v0.7.1 sound lab stops music on create (`sfxMusic(MUSIC_CTX_NONE)`) and gets a way back to the music lab only if it fits without changing its layout tests in a risky way (optional).
- **L15 Title layout.** Spec §4.4 recommended layout: top-right [曲: オン 200×80][12][音: オン 200×80]; the hint becomes the 音 button's second line 「本体の消音も確認」. Verify no overlap with the logo and the build label at logical widths 1,280–1,584 (8 px steps) and ≥ 43 pt touch targets, in tests.
