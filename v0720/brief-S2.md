## Lead decisions for S2
- **L19 mood observer** `src/core/sfx-music-mood.ts` (≤ 200 lines, pure, no Phaser, no allocation per step, `stepSfxMood(state, t, dtS)` returning 0/1/2). Inputs are exactly the HUD-shown states of spec §5.1 (battle / tense / quiet / sink). Use the real field names from the telemetry; where §5.1 names a field that does not exist or means something else, pick the closest HUD-shown state, document it in the file header and the CHANGELOG, and test it. Holds and timing from `SFX_MUSIC_MOOD` on the game clock (pause stops it). Sinking (`hp <= 0`) fades music to 0 over `sinkFadeS`.
- **L20 no leaks (D5).** The observer must not read `enemyDx`, `enemyDy`, `enemySighted`, `pt.dx`, `pt.dy`, `pt.sighted`, `planeDistM`, `patrol.distM`, `detectRangeM` (pin this in tests/sfx-rules like sfx-loops). Fake-telemetry tests: an unseen destroyer / PT / seaplane that is close (only distance fields small) keeps the mood quiet. "敵影あり" alone never raises the mood.
- **L21 transitions.** The probe gate is ≤ 6 mood changes per minute in every probe case. Holds alone may not guarantee this (a detection that flickers every ~10 s can give ~10 changes/min). If any probe case exceeds 6/min, add the smallest deterministic limiter in the observer (e.g. a minimum dwell before falling, never delaying a rise to battle) and report before/after numbers. Rises are never delayed by more than the next 10 Hz decision.
- **L22 ducking keys.** U-M1: `alarm` −8 dB / 0.8 s. Design defaults (user not yet asked; keep them in config, listed in CHANGELOG as 設計の既定): `bell` −6/1.2, `torp_hit` −5/0.8, `blast_l` only at distance band ≤ `maxBand` −4/0.5, `light_on` −4/0.5. Menu UI sounds never duck. Ducking acts only on the music duck node, only while the context is running, and allocates nothing.
- **L23 headroom (must measure, then fix if needed).** S0 measured the battle mix exit peak at 0.33 (spec estimated 0.2), and the v0.7.1 SFX exit peak max is 0.712, so worst-case coincidence can exceed the §8.3 gate (exit peak < 0.9, 0% over 1.0). Extend `sfx-offline.mjs` to add the music bus with each probe case's mood timeline and the ducks, through the real limiter, over the 31 probe cases' busy and quiet 10 s windows. Gates (§8.3): exit peak < 0.9; 0% over 1.0; blast pop (head 0.3 s minus previous 1 s, no blast in the previous 1 s) ≥ 6.5 dB; median drop of cue/blast windows vs the v0.7.1 S5/IP4 table ≤ 0.5 dB (alarm ≤ 0.2 dB); menu UI ≥ 12 dB over music (S1: 15.2 dB worst). If a gate fails, choose the smallest change that passes and keeps U-M1's character (candidates: lower the battle layer's level within the ±1.5 dB band, deeper/longer `blast_l` duck, widen `blast_l` to band ≤ 2) and report the numbers for each option you tried. Do not route music through the one-shot limiter (D6) unless every other option fails — then stop and explain.
- **L24 pause blip.** S1 noted that if the pause happens while the context is suspended (e.g. the app went to the background, which also opens Pause), the bus only fades after resume, so mission music can be heard for 0.1–0.25 s on the pause screen. Fix it in S2: on the first decision after the context becomes running with `paused` true, set the bus to 0 at once (no ramp). Test it with the fake context.
- **L25 lab rows.** Row 1 「任務の曲」: 静か／緊張／戦闘／自動（8 秒ずつ回す）／止める. Row 2 「効果音と一緒に」: 静か＋エンジンと海／発見＋警報／戦闘＋砲声と爆発 (listener at (0, 0), real distance bands via `sfxAt`, cues via `sfxCue`, loops via `sfxLoops`, so levels and ducking match the game). The 4th button 「命中＋スロー」 belongs to S3 (slow-mo treatment); leave a slot or add it in S3. Lab buttons stay `silent`. Building rules as in S1 (「作成中…」, play as continuation of the tap, second tap stops). Keep `music-lab-scene` ≤ 250 lines (split helpers into ui/ or a small systems helper if needed).
- **L26 title pick may change.** The user is auditioning A/B/C now. If they pick B or C, the lead changes `MUSIC_TITLE_DEFAULT_ID` (one constant + pins). Do not write code or tests that assume A is the default; derive from the constant.
