## §1 設計の決め

- D1（方式）: 先に作るループの層（§2 の (a)）。作曲は音符で、合成は音符の塊を数フレームに分けて 1 本の標本へ描く。任務の 3 層は同じ時刻に始めた繰り返しの音源で、音量だけを変わった時に動かす。
- D2（置き場）: 定数 `config/sfx-music-config`（新・何も import しない）、作曲と合成 `assets/sfx-music-*`（純粋・node で回る）、段の観測器 `core/sfx-music-mood`（テレメトリを読むだけ）、再生 `systems/sfx-music-player`（構造の型）。名前を `sfx-` で始める＝tests/sfx-rules の作法（Math.random なし・毎フレームの口で確保なし・import の許可表・300 行）が自動で効く。
- D3（context）: Phaser の `game.sound.context` を 1 つだけ（v0.7.1 D3）。曲の音源を始めるのは running・消音でない・曲がオン・標本がそろった時だけ（R2）。
- D4（作る時）: Boot では作らない。効果音の 1 フレーム 1 本の列（Boot の後 約 25 フレーム＝26 本から ui_tap を引いた数）が終わった次のフレームから、1 フレームに決まった量（§2.3）。作る順は「今の場面の曲 → 既定のタイトルの曲 → 任務の家族」。試聴の場の候補は押した時に同じ形で。
- D5（漏らさない）: 任務の段は HUD が文・色・帯で出している状態だけから決める（§5.5）。「敵影あり」だけでは上げない（U-M1 は「見つかったら」）。
- D6（つなぎ）: 曲の束は単発のリミッタを通さず master へ（v0.7.1 S3 のループと同じ理由）。S3 から、ループの束と曲の束は 1 つの低域通過（命中スローの「ベッドの濾波器」）を通る。単発は今のまま。
- D7（曲のオン／オフ）: 保存の鍵 `night-hunters.music`（'0' でオフ・既定オン）。曲だけ止める。「音: オフ」の間は曲も鳴らない（master 0。音源は止めて電池を守る）。
- D8（場面の口）: Title と Result が「メニュー」、`MissionSfx` が「任務」を頼み、任務の終わりは「任務なら外す」（release。§4.2）。Briefing は触らない＝Title の曲が続く（許可表を広げない）。
- D9（下げる）: 警報（発見・空襲の予告・識別の要求＝どれも `alarm`）で −8 dB（U-M1）。設計の既定（ユーザー未確認）: 鐘 −6・魚雷の命中 −5・近い大きい爆発 −4・探照灯 −4 dB。
- D10（一時停止・Result。設計の既定＝§11 O3）: 一時停止は曲もループと同じく 0.15 秒で消し、再開で戻す。Result は鐘（U-C のまま）の後、帰投 2.2 秒・それ以外 3.0 秒でタイトルの曲を頭から 2 秒で上げる。結果の曲（ジングル）は作らない。

## §2 方式の比べと推し

条件: 音のファイルなし・iOS Safari／PWA・Phaser の context 1 つ・毎フレームの確保なし・遅れて作る・buffer は 22,050 Hz モノ（Float32 で 1 秒 88.2 kB）・今の loop-player（音源は場面ごとに作り buffer 全体を繰り返す・目標は 10 Hz・変わった時だけ）。

| | (a) 先に作るループの層 | (b) 先読みの音符の順序器 |
|---|---|---|
| 主の糸の止まり | 音の糸が buffer を回し続ける。止まりで遅れるのは段の移りだけ（止まり＋0.1 秒） | 先読み 0.2〜0.5 秒より長い止まり（任務の作成・GC・低電力モードの 30 fps）で音符が抜けるか、遅れて一斉に鳴る（§7 の「積んだ音が一斉に鳴る」と同じ形） |
| 記憶 | 標本 1 秒 88.2 kB。タイトル 18〜30 秒＝1.6〜2.7 MB、任務 21.3＋21.3＋5.3 秒＝4.2 MB。ゲームの常駐 ≤ 7.2 MB（上限 180 万標本）＋効果音 2.58 MB | 楽器の単発 20〜25 秒（高さは rate）＝約 2 MB。rate を使わなければ約 6 MB |
| 作る時間（実測から） | 効果音の合成（雑音と濾波の連なり）は音 1 秒 約 10 ms（v0.7.1 S2）だが、曲は波形表で音 1 秒 2.6 ms（A 相当 30.5 秒で約 80 ms）。1 フレーム 15 万単位で A 約 66 フレーム・任務の家族 約 60 フレーム（node で 1 フレーム約 1.2 ms） | 単発 25 秒ぶんで約 75 ms（効果音と同じ作り方なら約 250 ms）。長い標本なし |
| 変化・繰り返し | 18〜30 秒の輪が繰り返す（7 分の任務で静かな層は約 20 回）。段の移りで手触りが変わる | 種で毎小節変えられる。小節に合わせた移り |
| 音源・GC | 場面の移りで 1（メニュー）か 3（任務）。段の移りは書き込み 3 つ | 毎秒 4〜16 個（効果音の最大 毎秒 22 個に足される）＋音符ごとの予約 |
| 込み入り | 再生は loop-player ＋場面の重ね（約 250 行） | 先読み・声の割り当て・場面の移りの取り消し（約 400 行） |
| テスト・決定性 | 純粋な合成＝指紋・継ぎ目・頂・帯の割合。標本はビット同一、決めは偽の時計で決定的。オフラインの mix はそのまま | 偽の時計で予約を確かめる。実時間の回では予約がフレームの刻みで揺れる。mix は予約をまねる |

**推し (a)**。「作曲は音符（順序器の考え）、合成は音符の塊を数フレームに分けて描く」＝作る時だけの順序器。数:
- 速さ: 16 分音符が 22,050 Hz で整数の標本になるテンポだけ（63・70・75・90・98・105・126 BPM）＝継ぎ目と層の同期が標本の単位でぴったり。
- 予算: 1 フレームに 150,000 単位（波形表の 1 声の 1 標本＝1・FM＝3・雑音の打楽器＝2）。node で約 1.2 ms、iPhone の見込み ≤ 4 ms。音符の途中では切らない＝分け方に依らずビット同一（試験）。
- 発振は波形表（2,048 点・線形補間・オクターブごとに 10 kHz で倍音を切った表＝22,050 Hz で折り返しなし）。包絡は掛け算の漸化式（標本ごとの exp なし）、輪の継ぎ目は 2 区間に分けて書く（% なし）。
- 書き場所は作業用の Float32Array 1 本（一番長い層の長さで 1 回だけ作って使い回す）→ 仕上げ（直流・頂 0.9）→ `createBuffer(1, n, 22050)` へ写す。
- 段の合図の短い曲（移りの一打）は作らない（効果音が既にその役）。

## §3 作曲（耳なしで作る）

### §3.1 独自性（CLAUDE.md §11）
- 旋律は手で書かない（source に旋律の音の並びを置かない＝tests/sfx-rules）。旋律は `composeMelody`（種つきの歩き）、和音は一般的な進行の表、リズムは型の表だけから。
- まねない（計画と docs にだけ名前を書く）: 軍艦行進曲・Anchors Aweigh・Victory at Sea・海行かば・Das Boot・ラッパの号令（起床・消灯）・ゲームと映画の曲（艦これ・World of Warships・Silent Hunter・Call of Duty など）。
- 決まり（試験で固定）: 主和音の分散を 4 音以上続けない（ラッパの型）・5–1–3–5 のファンファーレで始めない・句の頭で同じ音を 3 回以上打って 4 度以上跳ばない（行進曲の決まり文句）・同じ 4 小節を 3 回以上そのまま繰り返さない。
- 種は S0 の道具が「決まりを全部通る最初の種」を探して定数にする（ゲームの中では探さない）。最後はユーザーの耳: 試聴の場に「知っている曲に似ていたら教えてください（その案は作り直します）」。

### §3.2 作曲器 `assets/sfx-music-compose`
- 音は MIDI の番号（440 × 2^((n − 69)/12) Hz）。旋法（エオリア・ドリア・和声的短音階・長調）・進行（1 小節 1 和音）・リズムの型（候補ごとに 4〜6 個）。
- 旋律: 強拍は和音の音（≥ 80%）、順次 70%・跳躍 30%（跳躍の後は逆向きの順次）、音域の上下限、4 小節目は 2 度か 5 度で半終止、8 小節目は主音、5〜6 小節目は 1〜2 小節目の動機の変形。
- 出力は音符の表（楽器・始めの標本・長さ・音高・強さ）。作るのは作曲の 1 回だけ（作る時の確保は可）。

### §3.3 楽器（iPhone の本体は約 300〜400 Hz より下がほとんど出ない）
- パッド（鋸の表 3 声 ±3 cent・立ち上がり 1.5 秒）、鈴（FM 3.5:1・減衰 0.9〜1.8 秒・D5〜D6）、はじく音（明るい短い鋸・減衰 0.2〜0.4 秒。低音はこれ）、金管風（立ち上がりの後に倍音を明るく・0.15 秒からビブラート）、小太鼓・トム・リム（雑音の帯＋胴。胴は 180 Hz 以上）、うねり（雑音の帯 400〜1,600 Hz）。
- IP1〜IP2 の教え（長く鳴る低い正弦は本体で「ポンっ」）: 200 Hz より下の基音を 0.4 秒より長く鳴らさない（鳴らすなら 2〜6 倍音が 70% 以上）。層ごとに 400 Hz より上 ≥ 60%（B は ≥ 55%）・200 Hz より下 ≤ 12%。

### §3.4 大きさ（出口＝master の後の RMS。v0.7.1 の実測と並べる）
- メニュー −24 dBFS（UI の音はリミッタの後の出口で頂 約 0.3＝−10 dBFS なので、曲の RMS より約 14 dB 上）。任務: 静か −33・緊張 −30・戦闘 −27 dBFS（巡航のエンジン 約 −31・静音 約 −39、撃ち合いの混む窓の出口 −16〜−19 dBFS の下＝U-M1「静かに」）。
- 標本は頂 0.9。束と層の音量は「目標 ÷（標本の RMS × master 0.8）」で config に書き、テストが ±1.5 dB で固定。曲の最初の音は 2 秒で上げる（イヤホンで驚かせない）。

### §4.2 場面の移り
| 移り | 曲 |
|---|---|
| Boot → Title（初回） | 作れていて context が動いたら（iOS は最初のタッチの後）メニューの曲を 2 秒で上げる。最初のタップは待たない（ui_tap は Boot で作り、曲は列の後） |
| Title ⇄ Briefing・タブの切り替え（restart） | 同じ曲が続く（同じ場面の頼み直しは何もしない） |
| Briefing → Mission＋Hud | メニューを 1.2 秒で下げて止め、任務の 3 層を同じ `when` で始めて L0 を 3 秒で上げる（S1 は任務の曲がまだ無い＝消えるだけ） |
| Mission → Result | 任務の層を 0.5 秒で止める。鐘の後（帰投 2.2 秒・それ以外 3.0 秒）にメニューの曲を頭から |
| Result → Briefing（もう一度）／Title | メニューの曲が続く（遅らせの途中なら予定どおり始まる） |
| 一時停止 → 任務をやめる → Title | 任務の層を止め、Title でメニューを頭から |
| ?debug の直行（Boot・Result → Mission） | 任務の層。待っていたメニューの遅らせは上書き |
| ?sfxlab | 曲の試聴の場（`MUSIC_CTX_LAB`）。効果音の試聴の場では曲を止める |

- **順の落とし穴**: Phaser 3.90 の `SceneManager.processQueue` は `for (i = 0; i < this._queue.length; i++)`＝処理中に足された op も同じ輪の後ろで処理する。Mission の SHUTDOWN が足す「Hud を止める」は、Result・Title の start（＝create）の**後**に来る。任務の終わりで「曲を止める」と頼むと、Result・Title が頼んだメニューの曲を消す。→ `MissionSfx` は `sfxMusicRelease(MUSIC_CTX_MISSION)`（今の場面が任務の時だけ外す）。tests で両方の順を固定。
- 音源の数: 落ち着いた時は 0・1・3、移りの最中も ≤ 6（古い組は予約の `stop(when)`。止めかけの組がある時にまた移れば、その組は 30 ms で止める）。

### §4.3 一時停止・消音・曲のオン／オフ
- 一時停止（`MissionSfx` の PAUSE・RESUME）: 曲の束を 0.15 秒で 0、再開で戻す（音源は止めない）。命中スローの濾波器は §6.3。
- 「音: オフ」: master 0（今のまま）。曲の音源は 0.15 秒の後に止め、「音: オン」で場面の曲を頭から（任務は今の段で）。
- 「曲: オフ」: 曲の束を 0.3 秒で 0 → 音源を止める。「曲: オン」で作り直す。保存は Safari とホーム画面のアプリで別（v0.7.1 と同じ）。
- 試聴の場は場にいる間だけ「音」「曲」とも鳴らし、出る時に保存の値へ戻す（v0.7.1 の場と同じ）。

### §4.4 置き方（論理 px。tests の見積もり `textWidthPx`＝ASCII 0.602・かな漢字 1.0 × 字の大きさ）
- Title の右上（今は［一言 2 行 180 px］［音 200 × 80］）: 「曲」を左に並べると論理幅 1,280 で一言の左端が 652＝ロゴ（468〜812）にかかる。→ **推し**: 右上に［曲: オン 200 × 80］［間 12］［音: オン 200 × 80］（1,280 で 844〜1,044・1,056〜1,256。ロゴとの間 32 px・25 字のビルド番号の右端 776 との間 68 px。1,584 で 1,148〜1,560）、一言は「音」ボタンの 2 行目「本体の消音も確認」（17 px で 136 px＝余白を引いた幅 136 に収まる）。代わりの案: 「曲」を左上（24〜224）に置き、一言は今のまま。
- 一時停止: 「曲」を下の段の「音」のすぐ上（同じ x・320 × 96・y 488〜584・「音」との間 16）、黒の下敷きを足す。下の段の 3 つは今のまま（1,280 で左右の間 136 px）。
- 題は「曲: オン」⇄「曲: オフ」（26 px で 109 px ≤ 136）。HUD には置かない（hud-ab を変えない）。

### §4.5 つなぎと音量の段
```
声 16 → 単発の束 → リミッタ（−10 dB・12:1）→ 立ち上がり → master 0.8 → 出口
ループ 5 → ループの束 0.5 ──────┐
曲の層 ≤ 3 → 曲の束 → 下げる ─┴→（S3）ベッドの濾波器（低域通過・ふだん 20 kHz）→ master
```
- 頂の余り: S5・IP4 の出口の頂の最大 0.712。戦闘の曲の頂（出口）約 0.2 が重なると 0.91 → 爆発で −4 dB 下げる（D9 の設計の既定）と 0.85。門は実測の出口の頂 < 0.9（§8.3）。
- 濾波器を 20 kHz で常に挟む: 22,050 Hz の標本（上は 11 kHz）では 0.3 dB 以下の差。単発は通らない。

### §4.6 下げる（ducking。`SFX_MUSIC_DUCK`＝鍵 → dB・hold 秒）
- `alarm` −8 dB・0.8 秒（U-M1）。設計の既定: `bell` −6・1.2、`torp_hit` −5・0.8、`blast_l`（帯 ≤ 1）−4・0.5、`light_on` −4・0.5。
- エンジンが鳴らせた時（`fire` の後）に表を引く（確保なし）。下げる音量のノードに 2 つの予約（時定数 0.03 秒で下げ、hold の後に 0.25 秒で戻す）。下げている間の次の合図は、深いか長い時だけ予約を直す（0.5 秒に 2 回まで）。メニューの UI の音では下げない。

### §5.2 間と移り（`SFX_MUSIC_MOOD`）

## §6 命中スローの音（論理と data は変えない）

### §6.1 読む所
- `slowMoLeftS` は MissionWorld の公開の欄（不発でない魚雷の命中・撃破（jp_03 以外）・自艇の沈み始めで 1.2 秒。`updateFrame` で実時間を引く）。テレメトリに欄は無い。
- 推し: `world-art`（許可表の中）が作成で `registerSfxSlowMo(w)`（型は `{ readonly slowMoLeftS: number }`＝読むだけ）、破棄で null（聞き手の登録と同じ形）。テレメトリの書き手・論理のファイルは触らない。
- 読むのは `sfxLoops`（Hud の update から毎フレーム）の中の 1 回。`slow = src !== null && src.slowMoLeftS > 0` をエンジンへ渡し、エンジンは立ち上がり・立ち下がりの時だけ書く。

### §6.2 鳴らし方（`SFX_SLOW` の案。既定は §11 O2）
| 案 | ベッド（ループ＋曲） | 単発 |
|---|---|---|
| A（推し） | 濾波器 20 kHz → 1,100 Hz（時定数 0.04 秒）、ループの rate × 0.8・曲の rate × 0.85（時定数 0.06）。終わりは時定数 0.25 秒で戻す | そのまま（爆発・魚雷の命中は鋭いまま＝ご褒美の音を濁さない） |
| B | 濾波器だけ | そのまま |
| C | 何もしない（v0.7.1 と同じ） | そのまま |
- ループの rate は `sfxLoops` が目標の rate に純粋な関数 `applySfxSlowRate(targets, factor)` で掛けてから loop-player へ（今の「変わった時だけ書く」がそのまま効く）。エンジンの最小 0.75 × 0.8 = 0.6 ≥ 0.5（L6）。
- 曲の 3 層は同じ予約（同期は崩れない）。書くのはスロー 1 回につき 濾波器 2・曲の rate 2 × 3、ループは loop-player の変わった時だけ。曲の段の下げ（−5 dB の魚雷の命中）と重なってよい。

### §6.3 関わり
- 一時停止の間は `slowMoLeftS` も止まる（Mission が止まる）。ベッドは消えているので聞こえない。再開で残りが進む。
- 任務の終わり（Hud の SHUTDOWN の `sfxLoopsStop`）と `MUSIC_CTX_MENU` では濾波器と rate を必ず戻す（スローの途中で終わっても Result・Title の曲がこもらない）。
- jp_03: 撃墜・座席でない艇ではスローしない。ただし操作中の隊長艇の本当の沈没（240 秒の決着の後・最後の 1 隻＝`evacSinkLeader` が false）は `MissionWorld.hitBoat`／`sinkBoat` を通って 1.2 秒のスロー（§12）。同じ扱いで鳴る。

### §6.4 テスト
- 偽の context: 立ち上がりで濾波器 1・曲の rate 3 の書き込み、続く間は 0、立ち下がりで戻す、案 B・C、一時停止・消音・曲オフの途中、SHUTDOWN の途中、MENU で戻る。`applySfxSlowRate` は確保なし。
