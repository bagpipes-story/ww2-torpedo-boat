## Lead decisions (design defaults — the lead reports them to the user as unconfirmed defaults)
- **D1 Trigger** (all at once, per ship, per step): historical on; `detected` true (the existing detection incl. its 8 s hold = "the enemy knows the boat is there"); `losBlocked` true; range ship→boat ≤ `max_range_m` 500; `canFire`; boat afloat. Pair mode: blind fire targets the player boat only (escort unchanged).
- **D2 Aim = the smoke, not the boat.** Keep a per-ship "last seen" point (boat position on the last step the ship had the boat lit or LOS clear while detected). Blind aim point = a random active smoke puff whose centre is within `puff_search_m` of the last-seen point (uniform pick among those; if none, the last-seen point), then a uniform disc scatter of radius R(d) where d = ship→aim distance: R = lerp(`scatter_min_m` at `min_range_m`, `scatter_max_m` at `max_range_m`), clamped. No lead (enemy cannot see speed). Shells fly and hit-test exactly as normal shells (`pointNearBoat` with splash radius) — a moving boat escapes the old point; a boat sitting in its smoke gets hit more as the ship closes. Damage = normal shell damage.
- **D3 Cadence**: each gun fires at its normal rate × `rate_factor` (design start 0.5 — blind fire is slower, sights have nothing to lay on). Cooldowns must not carry negative backlog (same rule as today).
- **D4 Target band (design default, tune with a probe before hand-back):** a stopped boat (Elco 80) sitting at the last-seen point inside a fresh smoke screen, one destroyer (Mutsuki-type data), per gun shot P(hit) ≈ 1–3 % at 500 m, ≈ 4–8 % at 300 m, ≈ 10–20 % at 100 m; monotone rising as range closes. Also report the normal lit-fire per-shot P(hit) at the same ranges for comparison, and expected hits per 30 s in smoke at 500/300/100 m. If the band looks wrong for play (e.g. a 30 s smoke stay at 100 m sinks the boat almost surely), say so and propose numbers; do not silently change the band.
- **D5 Rng**: a new stream seed+21 per world (one `SeededRng`, created only when historical is on AND the mission has smoke-capable player boats; otherwise not created at all). Blind fire draws only from it. The normal gun rng is never touched by blind fire.
- **D6 Data**: `hit_rate_model.json` → `historical_mode.smoke_barrage` { `max_range_m` 500, `min_range_m`, `scatter_max_m`, `scatter_min_m`, `puff_search_m`, `rate_factor`, `source` with the user's request summarised and "design" }. Validator in the existing historical-mode loader (all finite, 0 < min < max, scatter_min ≤ scatter_max, 0 < rate_factor ≤ 1); tests for the validator.
- **D7 Pure core**: new `src/core/smoke-barrage.ts` (no Phaser; no allocation per step; fixed-size state per ship): state {lastSeenX, lastSeenY, hasSeen, cooldowns per gun}, `noteSeen(...)`, `stepBarrage(...)` that decides fire/no fire and the aim point and launches via the existing shell pool (`launchShell` from shells.ts with zero velocity lead and the computed scatter). Unit tests: trigger table (each condition off → no fire), range monotonicity of R, aim inside puff_search, no draws when not triggered, determinism.
- **D8 Wiring**: `EnemyFire` gets an optional barrage part (null in normal mode → old code path byte-for-byte the same order). Pass the smoke state/params to it from where `losBlocked` is computed (`systems/destroyer-step.ts` and any other caller of `EnemyFire.step/stepPair` — find all). Shell visuals, muzzle flash, splashes, sfx: reuse existing events (blind shots are ordinary shells). Music mood follows HUD as today.
- **D9 HUD**: 2nd line event text 「煙の中へ乱射されている」 when a blind shell lands within `hud_near_m` (config, not data — e.g. 150 m) of the boat, shown with the existing 2nd-line clock rules (find the nearest pattern: strait-line-clock / anchor-lines). Only in historical mode. setText only on change. Mention in Briefing? No.
- **D10 Result/telemetry**: optional count of blind shells fired / hits in telemetry for the probe; Result line not required.
